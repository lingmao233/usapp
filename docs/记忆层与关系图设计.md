# 「我们」记忆层与关系图 设计文档

> 本文档是 2026-08 需求拷问答询后的最终共识，作为实施依据。
> 任何与本文档冲突的实现都应视为偏差，需先回到本文档修订再动手。

## 1. 背景与目标

现状：所有 AI 调用均为无状态单次调用，无记忆/画像/习惯机制；人际连接只存在于两个一次性产物（周报 `key_connections`、碎片相关推荐）；三条 AI 管线为手写固定串行。

目标：

1. AI 流程升级为**确定性工作流 + 分层记忆**——换模型供应商、换 AI 人格均不失忆。
2. 新增**关系图**界面：全图 + 默认聚焦"我"，回答"我跟谁关系最深"。
3. 新增碎片**隐私/公共**可见性与**评论/点赞**互动。
4. web 端交付并 **PWA 化**；微信小程序冻结维护。

## 2. 总体原则

- **记忆归属**：记忆是数据库里的一等公民数据，模型供应商是无状态计算工人，随时可换。
- **确定性工作流**：不引 agent 框架。三条手写管线（`pipeline.py` / `reports.py` / `wishes.py`）重构为最小统一任务层：步骤定义 + 失败重试 + 运行状态落库（消灭 AI 失败静默降级 mock 的问题）。
- **隐私铁律**：隐私碎片参与一切计算，但从不以任何形式出现在别人的屏幕上——原文不行，摘要不行，标签也不行。**过滤永远在服务端**。

## 3. 数据模型

### 3.1 既有表变更

- `fragments` 新增 `visibility TEXT NOT NULL DEFAULT 'public'`（`'public' | 'private'`），存量数据迁移为 `public`。

### 3.2 记忆层（第 2 期）

- `user_profiles`：每 account 每 circle 一行。话题偏好、活跃习惯、愿望倾向等 AI 蒸馏画像（结构化 JSON）+ 更新时间。
- `pair_relationships`：每 circle 内用户对一行（14 人圈最多 C(14,2)=91 行）：
  - 四个信号分量分数（见 §4）
  - 共同主题列表：每条主题带**来源可见性标记**（`public-public` / `private-public` / `private-private`）
  - 关系摘要（模板拼装文案，非 LLM 自由文本）
  - dirty 标记与更新时间

### 3.3 互动（第 4 期）

- `comments`：`id, fragment_id, author_id, parent_id(NULL=顶级), content, created_at`。楼中楼。
- `likes`：`id, fragment_id, user_id, created_at`，唯一约束（fragment_id, user_id），点赞可取消。
- 仅公共碎片可被评论/点赞（服务端校验）。

## 4. 亲密度算法

- 分量全部落库，**总分在读取时现算**（加权和，零成本）；某信号无数据时按非零信号归一化。
- 权重：**语义相似 0.35 / 互动 0.30 / 共同愿望 0.20 / 共同主题 0.15**。调权重无需重算。
- 互动细分：**1 评论 = 3 点赞**；**单向评论只得一半评论分，对方回复后补满**；点赞双向计分（单向打折）。
- 语义与主题分量对隐私/公共碎片**同等权重**（隐私碎片照常参与计算）。

### 刷新机制

- 互动计数：评论/点赞写路径实时累加（一次 upsert）→ 图上即时变化。
- 语义/主题分量 + LLM 画像/摘要：每晚批处理（dirty flag，只算当天有活动的用户/用户对），周报生成前强制补跑一轮。
- 14 人圈一晚最多约 105 次 LLM 调用（14 画像 + 91 关系摘要），成本可忽略。cron 排在每日备份（3:17）之前。

## 5. 隐私模型

### 5.1 观看者相对的可见性矩阵（共同主题）

| 主题来源 | 全体成员可见 | 仅对当事人双方可见 |
|---|---|---|
| 公开 + 公开 | ✓ | ✓ |
| 我隐私 + TA 公开（我视角） | ✗ | ✓（仅我能见） |
| 隐私 + 隐私 | ✗ | 只提示"存在一个共同的秘密愿望"，**不揭晓主题** |

- 秘密愿望提示只说存在、不说主题：避免单方反推（若我只有一个秘密愿望，报主题即泄露对方秘密）；"去问问 TA"本身成为一次真实对话。
- 图数据按观看者各一份，服务端按请求者身份过滤后下发，无权内容不进 API 响应。91 边 × 14 人规模，逐请求现算即可。

### 5.2 各功能边界（隐私碎片）

- 相关推荐：不出现在别人的推荐里。
- 共同愿望：隐私愿望不触发对他人可见的匹配提示。
- 周报：对外内容只引用公开碎片。
- 知识库：隐私链接不归档。
- 碎片墙：默认 feed = 全圈公开碎片 + 我的隐私碎片；作者筛选（全部 / 我（含隐私）/ 各成员（仅公开）），`GET /fragments?author=` 服务端过滤 `visibility='public' OR author=我`。

### 5.3 反爬链接处理

小红书/抖音等反爬平台打不赢也不打，绕过：

1. 维护已知反爬域名清单，命中直接跳过抓取。
2. 抓取失败降级链：用户备注 > 链接标题/域名元信息；AI 分类与摘要基于备注生成；知识条目标记"正文未获取"。
3. 发布时检测此类链接且无备注 → 轻提示"这个链接 AI 读不到内容，补两句吧"，不强制。

## 6. 关系图 UI

- **视角**：全图 + 默认聚焦"我"，点任意成员切换焦点。
- **护栏**：边上不显示精确分数（亲疏映射为线条粗细分档）；无排行榜式排序；详情文案只走正向叙事。
- **渲染**：自绘 SVG 辐射布局，零新依赖。
  - "我"固定居中，其他成员在圆周上，**到圆心距离 = 亲密度**（越近越亲）。
  - 焦点切换用 FLIP 动画重排。
  - 点击连线 → 底部抽屉展示共同主题（已按观看者过滤）。
  - 秘密愿望连线加小标记（仅当事人可见）。
- 入口：第 4 个 tab；同期启用 react-router（已装未用，push 深链接也需要）。

## 7. 互动与内容形态

- 楼中楼评论（`parent_id`），点赞可取消；无通知中心，提醒靠 PWA push。
- 碎片可附链接；链接是引用，备注才是正文。

## 8. 平台策略

- web + PWA 一体推进：manifest + service worker + 图标 + push（iOS 16.4+ 已安装 PWA 支持 web push）。
- 微信小程序冻结维护：新功能不同步，双端漂移不再扩大。
- 将来上架应用商店走 Capacitor 套壳，web 代码 100% 复用，不返工。

## 9. 工程约束

- pytest 覆盖：亲密度算法、viewer-relative 可见性过滤（"算错分/泄隐私"级别的地方不裸奔）。前端测试本期不碰。
- 周报改为读 `pair_relationships` 持久数据，不再每次重算 key_connections。
- 现有约束不破：SQLite 单文件、2C2G 单机、AI 层 mock 降级（但降级必须显式记录/标识，不再静默）。
