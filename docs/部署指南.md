# 「我们」部署指南

> 目标：买一台 2C2G 的 Ubuntu 云服务器，照着这份文档让朋友能通过网址用上「我们」。
> 不需要运维经验。用一键脚本约 10 分钟，手动路径约 30 分钟。

---

## 0. 你需要准备的东西

| 东西 | 说明 | 没有行不行 |
|------|------|-----------|
| Ubuntu 云服务器 | 2C2G 起步，Ubuntu 22.04/24.04（腾讯云/阿里云/华为云都行） | 必须 |
| 服务器的 SSH 登录方式 | 买服务器时设置的密码或密钥 | 必须 |
| DeepSeek API key | [platform.deepseek.com](https://platform.deepseek.com) 注册充值（几块钱够用很久） | 不填也能跑（mock 模式），但强烈建议填 |
| 豆包（火山方舟）API key | [console.volcengine.com](https://console.volcengine.com) 开通「火山方舟」，创建 API key | 不填也能跑（mock embedding） |
| 域名 | 想用自己的网址（如 us.example.com）才需要 | 可先用 IP 访问，后续再加 |

## 快速路径（推荐）：一键脚本

上传代码到服务器后，一条命令搞定装 Docker、配 .env、构建启动、健康检查：

```bash
# 登录服务器
ssh root@你的服务器IP

# 上传代码（二选一；详见下方手动路径第 2 步）
apt-get update && apt-get install -y git && git clone <你的仓库地址> /opt/us-app
# 或者在自己电脑上执行：scp -r us-app root@你的服务器IP:/opt/us-app

# 一键部署（幂等，中断后重跑即可；--yes 跳过 key 询问）
cd /opt/us-app
bash deploy/setup.sh
```

脚本会依次：检测系统 → 装 Docker（已装则跳过）→ 装 compose 插件 → 问你 DeepSeek/豆包 key（可留空走 mock，也可先回车跳过以后补）→ `docker compose up -d --build` → 轮询健康检查，成功后打印 `http://<公网IP>:8000`。

注意事项：

- 脚本如果是用普通用户跑的，会把该用户加入 docker 组；组权限要**重新登录**才生效（脚本本次会自动用 `sudo docker` 兜底，不影响部署）。
- 之后更新代码：`git pull` 后重跑 `bash deploy/setup.sh --yes` 即可平滑重建。
- 跑完后记得在安全组放行 **TCP 8000**，然后直接跳到「5. 用域名 + HTTPS 访问」。

## 手动路径（备选 / 排障参考）

> 快速路径跑通了就不用看 1-4 节。脚本某一步失败、或你想弄清每步在做什么时，按下面的手动步骤来。

## 1. 登录服务器，安装 Docker

用自己电脑的终端（Mac 是「终端」App，Windows 用 PowerShell）：

```bash
ssh root@你的服务器IP
```

登进去之后，一键安装 Docker（Ubuntu 官方便捷脚本）：

```bash
curl -fsSL https://get.docker.com | bash
```

验证（两条都输出版本号即成功）：

```bash
docker --version
docker compose version
```

> 如果 `docker compose version` 提示找不到命令，执行 `apt-get install -y docker-compose-plugin`。

---

## 2. 把代码传到服务器

两种方式选一。

### 方式 A：git（推荐，以后更新方便）

```bash
apt-get update && apt-get install -y git
git clone <你的仓库地址> /opt/us-app
```

（先把代码推到 GitHub/Gitee 私有仓库即可。）

### 方式 B：scp 直接上传（在自己电脑上执行，不是在服务器上）

```bash
# 在自己电脑的项目目录的上一层执行
scp -r us-app root@你的服务器IP:/opt/us-app
```

> 上传前可以删掉 `node_modules` 和 `server/.venv` 减小体积，服务器上不需要它们：
> `rm -rf us-app/node_modules us-app/server/.venv us-app/dist`

---

## 3. 配置 .env

```bash
cd /opt/us-app
cp .env.example .env
nano .env
```

填上你的 key（没有就留空，自动进入 mock 模式）：

```ini
DEEPSEEK_API_KEY=sk-你的deepseek的key
DOUBAO_API_KEY=你的火山方舟key
```

保存退出：`Ctrl+O` 回车，`Ctrl+X`。

> Redis 不用配，docker-compose 会自动起一个，并通过 `REDIS_URL=redis://redis:6379/0` 连上。

### 可选：图片 caption（视觉模型）

碎片/愿望的图片会自动算多模态向量（只需 DOUBAO_API_KEY，无需额外配置）。
如果想让 AI 给图片生成一句中文描述（caption，参与分类打标签并进周报素材），
在火山方舟控制台开通一个视觉模型（如 doubao-vision 系列），把模型名或接入点 ID 填进 .env：

```ini
DOUBAO_VISION_MODEL=你开通的视觉模型名或接入点ID
```

不配（或调用失败）会自动跳过 caption，不影响任何现有功能。
配好后新发的图片碎片自动带 caption；历史图片碎片如需重算向量，跑一次回填：

```bash
cd /opt/us-app && docker compose exec -T app python scripts/reembed.py
```

---

## 4. 启动

```bash
cd /opt/us-app
docker compose up -d --build
```

第一次构建要几分钟（下载基础镜像 + 装依赖 + 构建前端）。看到 `Started` 字样就完成了。

**验证**（在服务器上执行）：

```bash
curl http://localhost:8000/api/health
# 返回 {"status":"ok","ai_mode":{"llm":"deepseek","embedding":"doubao"}}
# ai_mode 显示 deepseek/doubao 说明 key 生效；显示 mock 说明 key 没填或没生效
```

然后在自己电脑的浏览器打开 `http://你的服务器IP:8000`——能看到「我们」的首页，就大功告成了。

> 打不开？检查云服务器控制台的「安全组/防火墙」，放行 **TCP 8000** 端口。

---

## 5. 用域名 + HTTPS 访问（可选，推荐给朋友长期用）

### 方案一：Caddy（最简单，一行配置自动搞定 HTTPS）

Caddy 会自动申请和续期 HTTPS 证书，不用手动管。

```bash
apt-get install -y caddy
```

编辑配置：

```bash
nano /etc/caddy/Caddyfile
```

内容只有三行（把域名换成你的）：

```
us.example.com

reverse_proxy localhost:8000
```

重启生效：

```bash
systemctl reload caddy
```

打开 `https://us.example.com` 即可，小绿锁自动出现。记得安全组放行 **80 和 443**。

### 方案二：nginx + certbot（备选）

```bash
apt-get install -y nginx certbot python3-certbot-nginx
cp /opt/us-app/deploy/nginx.conf /etc/nginx/sites-available/us-app
# 编辑其中的 server_name 改成你的域名，root 改成 /opt/us-app/dist
nano /etc/nginx/sites-available/us-app
ln -s /etc/nginx/sites-available/us-app /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d us.example.com   # 按提示走，自动配好 HTTPS
```

> 注意：方案二用 nginx 托管静态文件时，需要前端构建产物 `dist/`。可以执行
> `docker compose cp` 或直接在服务器上 `apt install nodejs npm` 后 `npm ci && npm run build`，
> 也可以从本机 `scp -r dist root@服务器:/opt/us-app/dist` 上传。

## 6. 域名与备案提醒（重要）

- **服务器在大陆 + 用域名访问**：域名需要做 **ICP 备案**（云厂商控制台有入口，免费，周期约 1-3 周）。未备案的域名指向大陆服务器会被拦截；**用 IP 直连 8000 端口不需要备案**，内测阶段可以先用 IP。
- **服务器在香港/海外**：不需要备案，但朋友访问可能略慢。
- **以后做微信小程序**：小程序要求 **已备案域名 + HTTPS**，备案这件事迟早要做，建议买域名后尽早提交。

## 7. 日常维护

### 看日志

```bash
cd /opt/us-app
docker compose logs -f app      # 看应用日志，Ctrl+C 退出
docker compose logs -f redis    # 看 Redis 日志（一般不用看）
```

### 备份（SQLite 数据库）

备份脚本依赖 `sqlite3` 命令行工具，先装一下：

```bash
apt-get install -y sqlite3
```

数据都在 Docker volume 里。先找到 volume 在宿主机上的实际路径：

```bash
docker volume inspect us-app_us-data --format '{{.Mountpoint}}'
# 通常输出 /var/lib/docker/volumes/us-app_us-data/_data
```

手动备份一次：

```bash
bash /opt/us-app/deploy/backup.sh /var/lib/docker/volumes/us-app_us-data/_data
```

自动每天备份（凌晨 3:17，保留最近 14 份）：

```bash
crontab -e
# 加一行：
17 3 * * * bash /opt/us-app/deploy/backup.sh /var/lib/docker/volumes/us-app_us-data/_data >> /var/log/us-backup.log 2>&1
```

每晚记忆蒸馏（凌晨 2:40，排在备份之前；重算当天有活动的画像与关系分量）：

```bash
crontab -e
# 加一行：
40 2 * * * cd /opt/us-app && docker compose exec -T app python -m app.services.nightly >> /var/log/us-nightly.log 2>&1
```

备份文件在 volume 的 `backups/` 子目录里，定期 scp 下载到自己电脑更保险。
用户上传的图片存在 `server/data/uploads/`（volume 内），备份脚本已一并打包（`uploads-*.tar.gz`），无需额外操作。

### 更新代码后重启

```bash
cd /opt/us-app
git pull                      # 方式 B 上传的：重新 scp 覆盖
docker compose up -d --build  # 重新构建并平滑替换，数据在 volume 里不受影响
```

### 其他常用命令

```bash
docker compose ps           # 看容器状态
docker compose restart app  # 重启应用
docker compose down         # 停掉所有容器（数据保留在 volume）
df -h                       # 看磁盘占用（2C2G 机器建议偶尔看看）
```

## 8. PWA：装到主屏幕 + 收推送

「我们」是可安装的 PWA：装到主屏幕后有独立窗口、离线可打开已缓存的页面，
圈子里有人评论/点赞你的碎片时会收到系统推送（只推给碎片作者；自己评论/赞自己、
取消点赞都不会触发）。

> 前提：**必须用 HTTPS 访问**（第 5 节配好域名证书），或本机 localhost 调试。
> 裸 IP 走 http 时浏览器禁用 Service Worker，只能当普通网页用，装不了也收不到推送。

### iOS（iPhone / iPad，需 iOS 16.4+）

1. 用 **Safari** 打开站点（其他浏览器不行）。
2. 点底部分享按钮 →「添加到主屏幕」。
3. 从主屏幕的「我们」图标打开（这一步必须，推送只对已安装的 PWA 开放）。
4. 点顶栏（移动端在右上角菜单里）「开启通知」，允许系统弹窗即可。

### Android / 桌面 Chrome / Edge

1. 打开站点，地址栏右侧出现「安装」图标（或菜单里「安装应用」），点它安装。
2. 装好后在独立窗口里点顶栏「开启通知」，允许权限。
   不安装也可以直接在浏览器标签页里开启通知。

### 运维须知

- 推送用 VAPID 密钥对，**首次启动自动生成**，存 `server/data/vapid.json`
  （docker 里在 `us-data` volume 中持久化）。**别删它**——删掉后所有已订阅设备失效，
  大家需要重新「开启通知」。
- 设备换浏览器/重装系统后订阅自动失效，服务端发送时遇到 404/410 会自动清理，
  无需人工干预。
- 想关掉通知：在系统/浏览器的通知设置里关掉站点权限即可。

## 常见问题

**Q：`docker compose up` 报错端口被占用？**
8000 被别的程序占了：`ss -tlnp | grep 8000` 找到占用者，或改 docker-compose.yml 里 `ports` 为 `"8080:8000"` 后用 8080 访问。

**Q：朋友丢碎片后没有 AI 分类/相关推荐？**
看 `docker compose logs app`：`AI 模式：{'llm': 'mock', ...}` 说明 key 没生效——检查 `.env` 是否填对、是否在 `/opt/us-app/.env`（不是 `server/.env`），改完后 `docker compose up -d` 重建环境。

**Q：周报没自动生成？**
周报是懒触发：周一后第一位打开 App 的人会触发生成，约 10 秒后刷新即可看到。也可以手动触发：`curl -X POST http://localhost:8000/api/reports/generate -H 'Content-Type: application/json' -d '{"circle_id":"你的圈子id"}'`。

**Q：2C2G 够用吗？**
14 人小圈子完全够。SQLite + numpy 暴力检索在几百条碎片规模是毫秒级。瓶颈只可能是 LLM API 的响应速度，与服务器配置无关。
