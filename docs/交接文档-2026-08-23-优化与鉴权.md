## 4. 关键设计决策（防误改）

- **鉴权为什么是过渡期**：存量用户 localStorage 里没有 token，直接强制会把全部人锁外面；
  「带错必拒、无头先放」是最小惊扰迁移。设备令牌恒定（无过期/吊销）是单机自部署场景的
  取舍，需要吊销时改落表加盐
- **温度/思考参数必须单点**：`llm.resolve_temperature()` 与 `ai/reasoning.py` 是唯一口径
  （BUG-016/024 两次同坑）；新增任何 LLM 出口先接这两处
- **联网值拒绝判定靠品类先验而非对称阈值**：对称「差 10 倍拒」实测误伤正确值
  （能量棒/果汁用例），只保留 kJ 折算方向性——改校验前先跑 `tests/test_food_accuracy.py`
- **别名零手工表**：成分表方括号别名自动提取（`nutrition._alias_keys`），别建同义词字典
- **SSE 是进程内总线**：多 worker 部署会丢事件（部署保持单 worker；扩容换 Redis pub/sub）
- **`cleanup_pollution.py` / `supplement_food_nutrition.py` 生产都要跑一次**（错值清理 + 28 行补充数据）

## 5. 已知坑（会再踩的）

- `tests/test_config.py` 会 `importlib.reload(config)`：进程内可能同时存活新旧 settings
  实例（llm.py 持旧、懒导入模块拿新）——测试 patch 要打**全部活实例**
  （参考 `test_langmem_temperature_shares_llm_resolver` 的写法）
- TestClient 的 ASGITransport 会缓冲整个响应体：SSE 流式端点测试要么断言事件顺序
  （等流自然结束），要么直驱总线（`test_event_bus_cross_thread_delivery`），别想边流边读
- fakes 桩签名必须与门面同步：`web_search_food(model_per_100g)`、
  `treehole_reply(on_delta)`、`chat_messages(reasoning)` 都曾因签名漂移炸过一片
- Kimi/kimi.com 网关：k3 只收 temperature=1；`builtin_function` 回显要归一成 `function`；
  思考参数可能 400（各层已有剥参重试自愈）
- 上线部署顺序：`git pull && bash deploy/setup.sh --yes`（含全部 ALTER 迁移）→
  跑 `cleanup_pollion`… 注意拼写是 `cleanup_pollution.py` → 跑 `supplement_food_nutrition.py` →
