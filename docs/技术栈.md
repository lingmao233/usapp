# 「我们」技术栈全览

> 截至 2026-08。涵盖全部六期建设（MVP → 隐私地基 → 记忆层 → 关系图 → 互动 → PWA → 图片智能化）后的完整技术栈。
> 产品级设计决策见《记忆层与关系图设计.md》，本文只讲技术。

## 1. 一句话架构

单容器 FastAPI 托管 API + 前端静态产物，SQLite 单文件存储，AI 全部走外部 API（DeepSeek / 火山方舟），2C2G VPS 可跑 14 人圈。

```
浏览器 / PWA（React SPA）
  │  HTTP /api（vite dev 代理 → :8000）
  ▼
FastAPI（uvicorn :8000，同进程托管 dist/）
  ├── SQLite（WAL，单文件 + numpy 暴力余弦检索）
  ├── Redis（可选，连不上降级进程内字典）
  └── AI 统一抽象层（真实 API / mock 桩自动切换 + degraded 记录）
        ├── DeepSeek（chat，文本 LLM）
        ├── 豆包 embedding-vision（多模态向量，图文同空间）
        └── 豆包视觉模型（可选，图片 caption，env 开关）
```

## 5. AI 层（三模型分工 + 降级）

统一入口 `server/app/ai/__init__.py`：有 key 走真实 API，无 key 走 mock 桩（确定性，可测试），真实调用失败回退 mock 且记 degraded。

| 角色 | 模型 | 用途 |
|---|---|---|
| 文本 LLM | DeepSeek `deepseek-chat` | 分类打标签、摘要、共同愿望确认、行动方案、周报、画像、关系摘要 |
| 多模态向量 | 豆包 `doubao-embedding-vision`（`/embeddings/multimodal`，1024 维） | 文字+图片统一向量：相关推荐、共同愿望粗筛（≥0.7）、亲密度语义分量、知识库搜索 |
| 视觉 LLM（可选） | env `DOUBAO_VISION_MODEL`（如 doubao-seed-evolving，配 `DOUBAO_VISION_REASONING=minimal` 压思考成本） | 图片 caption，一句中文描述，落库复用 |

协作范式：**embedding 粗筛/匹配（像不像）→ caption 描述（是什么）→ LLM 生成（写成文）**。

**人格系统（每圈一个人格，圈与圈不互通）**：`circles.persona_preset` / `persona_custom` 两列，预写库 `PERSONAS` 五套（observer/sunshi/shudong/weekly/laba）在 `ai/prompts.py`，`resolve_persona` 解析（自定义非空优先，查不到回退 observer）。任何成员可经 `PUT /api/circles/{id}/persona` 换人格。周报 prompt 由纯函数 `ai.build_weekly_prompt` 组装：人格管语气（开头段），"事实与猜测的分寸"规则管事实（原样保留）。

**内容对齐（轻量 RAG 的 B1）**：①风格蒸馏——`generate_user_profile` 额外输入该用户近期公开发言摘录（公开碎片 + 公开碎片下的评论，≤10 条截 50 字），画像 JSON 多一个 `style` 键（口头禅/用词/emoji/句长）；②语录检索——`services/reports._collect_quotes` 取圈内公开碎片 + 评论原句，互动多的优先 + 最近的补足，≤8 条截 50 字进周报 prompt 当 few-shot。只用公开内容，隐私碎片及其评论永远不进 prompt。

**方案与真实数据**：「一起去」方案生成 = DeepSeek 抽取目的地（`PLAN_EXTRACT_PROMPT`）→ 高德 Web 服务查真实 POI/天气/驾车通勤（`services/amap.py`，未配 `AMAP_KEY` 整体回退纯 LLM 经验方案）→ DeepSeek 落地方案（`PLAN_PROMPT`：地点只用真实 POI、价格一律预估标注 + 跳转链接）。方案缓存进 `wishes.plan`（含 participants），每晚蒸馏顺带预生成；共同愿望匹配结果圈级缓存（`common_wishes_cache`，池子指纹自失效）。方案追问是轻量对话（`PLAN_CHAT_PROMPT`），会话存通用的 `chat_threads`/`chat_messages`（kind='plan'，为独立 AI 聊天页预留）。

## 6. 记忆层（是不是 RAG？）

**严格说不是教科书 RAG**——没有文档切块、没有向量数据库、没有在线问答时的即时召回。它是**三层记忆 + 离线蒸馏**：

1. **原始数据层**：fragments / wishes / comments / likes / knowledge_items + 每条碎片的 embedding blob。隐私碎片参与一切计算。
2. **蒸馏记忆层**：`user_profiles`（个人画像）+ `pair_relationships`（用户对四分量：语义 0.35 / 互动 0.30 / 共同愿望 0.20 / 共同主题 0.15；共同主题带来源可见性标记；秘密愿望只记数量）。每晚 cron 批量蒸馏（dirty 驱动），互动分量写路径实时更新。
3. **读取注入层**：总分读取时现算（加权和 + 非零归一化）；图 API 按观看者做服务端过滤；周报/摘要生成时把这些结构化材料喂给 LLM。

第 3 层"取结构化材料 → LLM 生成"精神上就是检索增强生成，但检索对象是**预算好的记忆表**而不是原始文档块——所以准确说法是：**蒸馏式记忆 + 检索增强生成**，召回发生在夜间，不在提问时。

## 7. 数据与隐私

- SQLite `server/data/app.db`（WAL）；手写 PRAGMA 迁移（无 Alembic）；17 张表
- 图片文件 `server/data/uploads/`（原图 + `_d` 展示图约定）
- 隐私铁律：隐私碎片参与计算、绝不出现在他人屏幕（原文/摘要/标签都不行），**过滤永远在服务端**
- 观看者相对可见性：public-public 全员可见；含我隐私来源仅我可见；双隐只提示存在

## 8. 部署运维

- Dockerfile 两阶段（node 构建 → python 运行时单容器）；docker-compose：app + redis
- `deploy/setup.sh` 幂等一键装机；`deploy/backup.sh` 每日 3:17 备份 SQLite + uploads（14 份保留）
- 每晚 2:40 cron 蒸馏：`python -m app.services.nightly`
- 一次性回填：`server/scripts/reembed.py`（embedding 换端点/维度后跑）
- HTTPS 推荐 Caddy（PWA 推送的前置条件）
