# 方案生成：类型人格与约束清单

> 2026-08-14 拷问答询共识。任何方案生成（`PLAN_*` prompt / `_plan_context` / `build_plan_prompt`）的改动必须先过这张清单；与本文档冲突的实现视为偏差（BUG-007 复盘产物）。

## 1. 架构原则

- **LLM 只选类型，路径与人格写死在服务端**：`PLAN_KINDS`（实现路径）+ `PLAN_KIND_PERSONAS`（类型人格）都在 `server/app/ai/prompts.py`，枚举外的 LLM 输出一律回退 `activity`。
- **方案=类型人格，周报=圈人格**，两套人格互不干扰，不叠加。
- **LLM 自检回路（审校修订）共识为不上**；质量靠 prompt 约束 + §4 样例手测闭环。某类错误反复出现且 prompt 改不动时，再针对那一类单独立项。

## 2. 类型 → 人格 → 路径总表

| kind | 人格 | 实现路径要点 | 高德 |
|---|---|---|---|
| `outing` 出行体验 | 会玩的朋友 | 有真实数据从中选地点；没有按品类推荐目的地类型 | 查（需品类词） |
| `learning` 学习技能 | 鼓励型教练 | 先肯定，再给入门步骤、装备与费用预估 | 可查（场馆品类词） |
| `dining` 聚餐吃喝 | 吃货朋友 | 选餐厅 + 凑时间 + AA 预算 | 查 |
| `activity` 活动/购物/小事 | 靠谱参谋 | 清单与渠道，不依赖地点数据 | 一般不查 |
| `meet` 约人聚会 | 热心撮合的朋友 | 怎么开口、凑时间、选活动；地点只是轻建议 | 不查 |
| `venting` 情绪倾诉 | 双形态（见 §3） | 不硬做正经方案 | 不查 |

判定输入只有愿望原文（`PLAN_EXTRACT_PROMPT`）；`need_real_data` 与 keywords 联动——**没有可搜品类词就一律不查高德**，人名/情绪词/自造词绝不当搜索词。

## 3. venting 双形态与情绪判断

分析步输出 `mood`（`negative|neutral|playful`，枚举外回退 `neutral`）：

- **非消极（neutral/playful）→ 损友人设**：一本正经玩梗（去睡觉/刮彩票范式），time/location/budget 放开玩，steps 前两步玩梗、**最后一步必须落一个真实可执行的小行动**
- **消极（negative）→ 温柔树洞人设**：不许玩梗；先接住情绪（不建议、不说教、不评判），再给一个今天就能做的积极小行动，结尾留陪伴感

## 4. 护栏（任何类型都不得违反）

- 严禁把愿望里随手提到的词（尤其**人名**）当成店名/地名写进方案；严禁"去地图上搜一下 XX"式步骤
- 玩梗不拿别人开涮；不复述被吐槽的人名；不给对抗/回避某个人的操作建议
- 价格一律区间 + "预估"；links 关键词只用品类词（情绪倾诉类可给空数组）
- 人格只管语气，地点/价格/时间等事实信息直给，不许编
- disclaimer 如实说明数据口径

## 5. 工程要求

- prompt 组装必须是纯函数（`build_plan_prompt`），类型→人格→路径映射有 pytest 断言锁死
- LLM 结构化输出的枚举/布尔字段必须防御解析（大小写、字符串布尔）
- mock 桩确定性产出全字段；新增字段 mock 同步
- 生成质量类事故修完按 `docs/BUG记录.md` 格式登记

## 6. 手测样例集（真实 key，改 prompt 后必跑）

`POST /api/wishes/{id}/plan` 逐条生成，对照预期形态：

| 样例愿望 | 预期 kind | 预期形态 |
|---|---|---|
| 想暴富 | venting + playful | 损友玩梗，收尾有小行动 |
| 想不工作，好累 | venting + negative | 树洞温暖，不玩梗 |
| 想学游泳 | learning | 鼓励 + 入门路径，可查游泳馆 |
| 想去海边 | outing | 高德真实 POI/天气（key 有效时） |
| 想吃火锅 | dining | 吃货口吻 + 真实餐厅 |
| 想找欧培昇玩 | meet | 围绕怎么约，人名不进地图搜索 |
